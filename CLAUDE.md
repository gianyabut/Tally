## Design changes

Whenever the user asks for any design-related change (layout, visual style, component look, copy placement, new screen or UI element):

1. **Consult Mobbin first.** Search it (the `mcp__mobbin__*` tools: screens, flows, sections) for how established apps handle the same pattern, and use those references to inform the options.
2. **Create 3 distinct mockups** for the user to choose from, before touching any code. Each mockup should note which Mobbin references inspired it, and stay within Tally's design system (tokens in `docs/README.md`, copy rules in `docs/CONTENT.md`) unless the change is about the design system itself.
3. **Wait for the user's pick**, then implement only the chosen option.
